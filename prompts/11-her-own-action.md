# 11 — 本人の一手を本人のものにする（09-26）

指摘: B2B 想定なのにログインが無い。調べた結果、**ログインはどの賞も要求していない**が、
2つ問題が出た。①`/me` を誰でも開けて「Withdraw authority」を押せる＝「本人だけの一手で
誰も取り消せない」という主張が実装で成立していない ②IDKit の賞が実質未達（`src/worldid.ts`
が単独のページに置かれたままで、製品の判断に一度も繋がっていない）。

**同じ一手で閉じる**＝権限を取り戻す操作の前に IDKit を置く。

## 指示（要点）

- 資格は Proof of Human（device）で足りる。**身元は要らない・要るのは「実在する人間で、
  前と同じ人」だけ**。強い資格を足すと賞の評価軸（最小十分）から外れる
- 専用の action を作る（承認用を流用しない）。ポータルの UI ではなく API で
- **クライアントの成功を権限に使わない**。ブラウザは証明をサーバへ渡すだけ
- nullifier は D1 に残す（Worker のメモリに置くのは 09-25 に一度やった間違い）
- **拒否経路を3つ実演できる形にする**: 証明なし／資格不足／Portal が拒否。
  どの場合も委任は手つかずであることを実際に確認する
- ログインを他の画面に作らない。B2B のセッション層は普通の作業で、ここで何も証明しない

## 決めたこと（私）

- ログイン一式は作らない。**作るのは「権限を取り戻す」1箇所だけ**——その1つだけが、
  実装されていないと主張が崩れる場所だから。残りは README で明示的に「作っていない」と書く
- 「検証を拒めば取り消せる」形にしない＝失敗は必ず「取り消されない」側に倒す
