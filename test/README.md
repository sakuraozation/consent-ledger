# tests

`bun test`。ネットワークも鍵も要らないので、CI でもそのまま走る。

**何を試しているか**——この作品が防ごうとしている失敗は crash ではなく**黙って通ること**なので、
守るべき不変条件はほとんど「ここで `allow` を返さない」の形になる。だからテストも
「**`allow` が出てはいけない場合**」に集中させてある。

| ファイル | 中身 |
|---|---|
| [`authority.test.ts`](authority.test.ts) | 権限の境界。渡していない範囲・引き上げた範囲・委任の消失・チェーンの役割の剥奪・**チェーンが読めない時に `allow` へ倒さないこと**（fail closed） |
| [`failure-paths.test.ts`](failure-paths.test.ts) | 壊れ方の向き。期限切れは `deny` でなく `ask`／事務所が扱う範囲は本人に振らない／承認の時間切れが「答えなかった」として残ること／証明の検証が通信の前に弾くこと |
| [`d1.ts`](d1.ts) | テスト用の D1。`bun:sqlite` の上に D1 の面だけを被せ、**本物のマイグレーションを当てて本物の SQL を走らせる**（スタブに差し替えるとスキーマとの食い違いが出ない） |

回帰として固定してあるもの:

- **取り消しが範囲を越えて巻き込まない**（2026-09-25 にデモ中に見つけた不具合。ある範囲の
  取り消しが、事務所が別の範囲に出し直した許諾まで殺していた）
- **引き上げた範囲の許諾が `allow` のまま通らない**（09-26。しかも理由が「本人が自分で
  答えた」と誤って名乗っていた）

**試していないもの**（正直に）: World と ENS への実通信、ブラウザ側の IDKit、画面の描画。
前二者は鍵と実機が要るので手で確かめ、結果は `FEEDBACK.md` と `specs/requirements.md` に
書いてある。
